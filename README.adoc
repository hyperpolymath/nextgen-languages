= Next-Generation Languages
:toc:
:toc-placement: preamble

A research portfolio and *coordination hub* for independent language projects in the Hyperpolymath ecosystem. This repository is an index and map: it does not build, host, or vendor the languages themselves.

====
**Start here:** this README is the short orientation; link:EXPLAINME.adoc[EXPLAINME] explains the boundaries and connections; link:docs/ecosystem-map.adoc[the ecosystem map] shows the projects by role; and link:languages/README.adoc[the language index] links to each canonical project. ====

== What this is

The portfolio gathers research into languages and language-like systems that make important structure explicit: resources, termination, deadlines, consent, ethics, topology, uncertainty, construction, continuity, and physical constraints. They are related by research interests, not by a shared compiler, runtime, or promise of mutual compatibility. Read each project's own documentation for its current implementation and evidence.

This repository's responsibilities are to:

* maintain the scoped portfolio registry and links to canonical repositories;
* explain project roles, boundaries, lineages, and cross-project dependencies;
* maintain cross-language status and evidence summaries without upgrading claims by implication;
* provide governance, navigation, and language-agnostic contributor orientation.

Language implementations, language-specific specifications, grammars, proofs, and tutorials belong in their own canonical repositories. The boundary is checked by `hooks/validate-coordinator-boundary.sh` and `hooks/validate-language-registry.sh`.

== Portfolio at a glance

The machine-readable registry in `.machine_readable/LANGUAGES.a2ml` is the authoritative list for this coordinator. It contains 17 records: 16 committed portfolio entries with human pointers, plus one exploratory/private TypeFix Zero record that is intentionally not a committed family member. The committed set includes the My-Lang dialect family, experimental KitchenSpeak DSL, Firmboot continuity-research prototype, and private index-only 007. Inclusion means *indexed here*, not mature, mutually compatible, or production-ready.

== Connected work: related, not all members

Several neighboring projects extend or study this work without being additional entries in the core language registry:

* **AffineScript surfaces:** link:https://github.com/hyperpolymath/cafescripto[CafeScripto], link:https://github.com/hyperpolymath/jaffascript[JaffaScript], link:https://github.com/hyperpolymath/lucidscript[LucidScript], link:https://github.com/hyperpolymath/pseudoscript[PseudoScript], and link:https://github.com/hyperpolymath/rattlescript[RattleScript] explore familiar syntax surfaces over AffineScript's resource-safety direction. Treat them as related surface projects, not five new core languages.
* **Foundations and research labs:** link:https://github.com/hyperpolymath/kategoria[Kategoria] explores routes through type-safety levels; link:https://github.com/hyperpolymath/panoply[Panoply] is an envelope-first safety-claim discipline. They are related to language design, but have different scopes.
* **Shared substrates and targets:** link:https://github.com/hyperpolymath/typed-wasm[typed-wasm] is a WasmGC target/ABI substrate; link:https://github.com/hyperpolymath/echo-types[echo-types] is a formal library for structured information loss. Neither is itself a member language here.
* **Teaching and application:** link:https://github.com/hyperpolymath/tentacles-agentic-syllabus[tentacles-agentic-syllabus] is a curriculum framework, not a language. Language-specific teaching materials remain with their owning projects.
* **Wiki tooling (Metadatastician estate):** link:https://github.com/metadatastician/berrywiki[BerryWiki] provides optional editing and navigation for ordinary Markdown wiki content. The portfolio wiki files remain in this repository and work without BerryWiki.
* **Language augmentation tools:** the `*-iser` projects apply selected ideas from a language to other codebases; they are tools, not implementations or language-family members. See the link:docs/ecosystem-map.adoc[map] for examples and boundaries.

The public GitHub estate search did not identify a `ziz` repository or a language project by that name. It is intentionally *not* guessed into the registry. If “Ziz” refers to a private repository or a different spelling/owner, its canonical URL and intended role are needed before it can be indexed accurately.

== Status and limitations

This is a research portfolio, not a unified language platform. Stages range from conceptual specifications to experimental implementations and partially verified cores. Readiness values are evidence-scoped; `TBD` means no coordinator-verified value, not a grade. The most recent cross-portfolio review is the link:docs/audits/2026-09-07-language-portfolio.md[7 September 2026 audit]; consult each upstream repository for changes since that snapshot.

The projects do not automatically share syntax, semantics, compilers, ABI, or release schedules. Connections in this repository are classified as **dependency**, **shared substrate**, **syntax surface**, **tool**, **curriculum**, or **research adjacency** so that a link does not imply an integration that has not been demonstrated.

== Checks for this repository

No language build is expected here. From the repository root, run:

[source,bash]
----
bash hooks/validate-language-registry.sh
bash hooks/validate-coordinator-boundary.sh
----

These check registry consistency and prevent language-specific implementation content from being copied into the coordinator. See link:QUICKSTART-DEV.adoc[the contributor quick start] for the full coordinator checks.

[WARNING]
====
**Open supply-chain follow-up:** `bash hooks/validate-sha-pins.sh` currently reports 29 workflow action references that use tags rather than commit SHAs. `.github/workflows/actions.lock` records tag-to-commit resolutions, but does not make those `uses:` lines immutable. The supported `gh actions-lock` tool could not be downloaded in this environment (release-asset transfer returned EOF), and the generated lock must not be hand-edited. Treat the SHA-pin check as outstanding until the lock tool can safely update workflows and lockfile together.
